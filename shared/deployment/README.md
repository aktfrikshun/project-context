# Deployment and operations

- Make releases traceable to an immutable revision.
- Prefer automated, repeatable, least-privilege delivery.
- Separate configuration from artifacts and manage secrets externally.
- Define health signals, ownership, rollback or forward-fix procedures, and recovery objectives.
- Use backward-compatible transitions for distributed contracts and data migrations.
- Record environment differences and manual gates.
- Verify deployments with observable, user-relevant checks.
- Document incident learnings as current guidance, decisions, or curated history.

Project-specific environments and procedures belong in the project's architecture and workflows.
