# UI guidelines

- Design for understandable tasks and recoverable mistakes.
- Meet the project's documented accessibility target; record exceptions explicitly.
- Use established design tokens and components before introducing variants.
- Provide meaningful loading, empty, error, success, and permission-denied states.
- Preserve keyboard operation, focus visibility, semantic structure, and readable contrast.
- Avoid encoding meaning through color alone.
- Treat user-facing language and localization as product contracts.
- Validate destructive actions proportionally to their reversibility.

Project-specific brand systems, supported devices, and interaction exceptions belong under that project.
